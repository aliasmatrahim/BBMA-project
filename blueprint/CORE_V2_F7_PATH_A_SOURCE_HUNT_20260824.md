## 4. Material lifecycle evidence from the workbook copy

The workbook copy materially strengthens the exit model in a way not captured by the current static M17 resolver.

### 4.1 Momentum is the continuation proof after Re-Entry

The workbook states, in substance:

- candle close outside Top/Low BB = Momentum;
- when Momentum appears, continuation is expected and another Re-Entry follows;
- after Re-Entry, if Momentum does **not** appear, the market is expected to rotate/reverse.

This is repeated in the summary/lifecycle section.

### 4.2 No Momentum after Re-Entry => close / TP

The workbook contains multiple mutually reinforcing statements:

- `Arah -> Reentry -> Tiada Momentum` leads to closing the position because the market is expected to reverse;
- after MHV -> direction -> Re-Entry, if no Momentum follows, **TP is mandatory**;
- the summary restates that if Re-Entry is followed by no Momentum, the trade should be taken profit before the market rotates back.

This is substantially stronger than a generic community suggestion because it appears as repeated teaching inside the product-linked `BBMA Home Course Workbook` structure.

### 4.3 Momentum after Re-Entry => continuation / next Re-Entry

The same workbook states:

- if Momentum occurs, wait for the next Re-Entry;
- after Re-Entry comes Momentum, and at Momentum the trader waits for the next Re-Entry;
- the canonical repeating sequence is expressed as `Extreme -> TP Wajib -> MHV -> CS Arah -> Re-Entry -> Momentum -> Re-Entry`.

This points to a **lifecycle-controlled profit/hold model**, not a universal one-shot outer-BB destination model.

### 4.4 Timeframe ownership warning

A contemporaneous 2015 CariGold Home Course promotion reproduces the following teaching attribution to Oma Ally in substance:

> entering on M15 and then taking profit from a Daily target is wrong; the trader must be clear which timeframe is being traded.

Source:
`https://carigold.com/forum/threads/trading-plan-paling-hot-2015-dapatkan-set-lengkap-bbma-home-course-study.585138/`

Because this is a forum reproduction/quotation rather than an authenticated original recording, it is not sufficient alone to define a deterministic formula. It is nevertheless important corroboration that **TP ownership is timeframe-sensitive** and that arbitrary cross-timeframe target escalation is not source-safe.
